# 資料庫設計

- 適用版本：2.0.0-alpha.3／alpha.4 開發中（遷移版本 `0005`）
- 資料庫：PostgreSQL 16（決策 D3：開發、測試、正式環境一律 PostgreSQL）
- 以程式碼為準：資料表定義在 `backend/app/models.py`，遷移在 `backend/alembic/versions/`。本文件與程式碼不符時，CI 的 `backend/tests/test_docs_sync.py` 會失敗。
- **維護規則**：每次新增或修改資料表、欄位、索引、遷移，都要同一個 PR 更新本文件。

## 1. 總覽

```
users ──< auth_sessions
  │
  ├──< watchlist                （每位用戶私人）
  └──< runs.requested_by ──< method_results
                          └──< ai_tasks.run_id

securities ──< price_bars           （未調整的每日價格）
           ──< corporate_actions    （派息、拆股）
price_revisions                     （來源修正前的舊值；按代號記錄，不設外鍵）

sec_tickers                         （SEC 代號 → CIK）
filers ──< filings                  （SEC 申報公司與每份申報）
       ──< filed_facts              （申報層：每個申報數字）
raw_documents                       （原始層：每份抓取的文件，filers／filed_facts 指向它）
filed_concepts                      （分類法科目的名稱與定義）

settings   （鍵值設定：AI 連線、品牌、限制、排程狀態……）

```

共同慣例：

- 時間欄位一律 `timestamptz`，以 UTC 保存；日期欄位（交易日、除息日）用 `date`。
- 用戶與估值的主鍵是 32 字元的 UUID（不含連字號）。
- 代號（`ticker`）一律大寫，最長 24 字元，經 v1.1.1 的嚴格檢查。
- 刪除用戶時：登入狀態、觀察名單一併刪除（CASCADE）；估值紀錄保留，`requested_by` 設為空值（SET NULL）。

## 5. 市場數據

設計見 `docs/決策紀錄與路線圖-v2.1.md` 第 4 節。原則：

- **只存未調整的數字**：拆股不會改寫歷史價格；調整後價格與總回報由 `price_bars` 加 `corporate_actions` 即時計算。
- **只新增、不改寫**：排程更新時，來源改動過的數字先把舊值寫入 `price_revisions`，才更新。
- 系統用過的每個代號都會被追蹤並每日更新，歷史自然累積。查不到任何數據的代號會被刪除，不追蹤。

## 6. 財報數據（原始層與申報層）

設計見 `docs/財報數據與估值架構.md` 第 2 節與路線圖第 3 節。解析在 `libs/sv_data`（不接觸資料庫），保存在 `backend/app/services/statements.py`。原則：

- **原始層永不修改**：每份抓取的文件以 gzip 原樣存於 `<APP_DATA_DIR>/raw/<來源>/<類別>/<SHA-256 前兩碼>/<SHA-256>.gz`，讀取時核對 SHA-256。內容相同的文件只存一份，再次抓取只更新 `last_checked_at`。
- **申報層只增不改**：同一期間在較新的申報中再次出現（重編）時，新增一筆，舊數字保留；SEC 後來不再列出的數字也保留。
- **精確數字**：`filed_facts.value` 用 PostgreSQL `numeric`，由 SEC 的 JSON 直接解析為十進位數，不經浮點數。
- 目前只有 SEC companyfacts 的「無維度」數字；分部等維度數字與公司自訂科目需要讀取每份申報的 XBRL 原文，在後續步驟加入。

## 9. 計劃中的資料表（alpha.3 起）

以下依 `docs/財報數據與估值架構.md`，落實時再移入上方各節：

- 財報的標準層目前**不另存資料表**：它是申報層（`filed_facts`）、規則版本（`libs/sv_data/rules/*.yaml`）、版本（最新／首次公布）、`as_of` 與股份分拆（`corporate_actions`）的確定函數，讀取時計算（一家公司約 0.1 秒）。估值開始使用標準層時，會把當次所用的數字、規則版本與 `as_of` 隨估值保存，保證可重現。
- 財報的檢查層同樣在讀取時計算：檢查規則（`libs/sv_data/rules/checks_general.yaml`）作用於標準層與已保存的 Yahoo 原始文件，得出每期品質等級。
- 調整方案（D12）：每個代號一個中央方案、每位用戶每個代號一個個人方案，全部版本保留。
- 組合分析（alpha.4）：保存的比較圖與最佳化場景。
