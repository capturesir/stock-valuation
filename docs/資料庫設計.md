# 資料庫設計

- 適用版本：2.0.0-alpha.2 起（遷移版本 `0003`）
- 資料庫：PostgreSQL 16（決策 D3：開發、測試、正式環境一律 PostgreSQL）
- 以程式碼為準：資料表定義在 `backend/app/models.py`，遷移在 `backend/alembic/versions/`。本文件與程式碼不符時，CI 的 `backend/tests/test_docs_sync.py` 會失敗。
- **維護規則**：每次新增或修改資料表、欄位、索引、遷移，都要同一個 PR 更新本文件。

---

## 1. 總覽

```
users ──< auth_sessions
  │
  ├──< watchlist                （每位用戶私人）
  └──< runs.requested_by ──< method_results
                          └──< ai_tasks.run_id

securities ──< price_bars           （未調整的每日價格）
           ──< corporate_actions    （派息、拆股）
price_revisions                     （來源修正前的舊值；按代號記錄，不設外鍵）

settings   （鍵值設定：AI 連線、品牌、限制、排程狀態……）
prices     （AI 模型價格表）
```

| 資料表 | 用途 | 加入版本 |
| --- | --- | --- |
| `users` | 用戶與角色 | alpha.2（0002） |
| `auth_sessions` | 登入狀態（Cookie 或令牌） | alpha.2（0002） |
| `watchlist` | 觀察名單（私人） | alpha.1（0001），alpha.2 加 `user_id` |
| `runs` | 每次估值（成功、失敗、取消都保留） | alpha.1（0001），alpha.2 加 `requested_by` |
| `method_results` | 每次估值的各方法、各情境結果 | alpha.1（0001） |
| `ai_tasks` | AI 任務的預估與實際用量 | alpha.1（0001） |
| `settings` | 系統設定（鍵值，JSON） | alpha.1（0001） |
| `prices` | AI 模型價格（US$／百萬 Token） | alpha.1（0001） |
| `securities` | 證券主檔（股票、ETF、匯率） | alpha.2（0003） |
| `price_bars` | 每日價格，未調整 | alpha.2（0003） |
| `corporate_actions` | 派息與拆股 | alpha.2（0003） |
| `price_revisions` | 來源修正過的數字的舊值 | alpha.2（0003） |

共同慣例：

- 時間欄位一律 `timestamptz`，以 UTC 保存；日期欄位（交易日、除息日）用 `date`。
- 用戶與估值的主鍵是 32 字元的 UUID（不含連字號）。
- 代號（`ticker`）一律大寫，最長 24 字元，經 v1.1.1 的嚴格檢查。
- 刪除用戶時：登入狀態、觀察名單一併刪除（CASCADE）；估值紀錄保留，`requested_by` 設為空值（SET NULL）。

## 3. 觀察名單與估值紀錄

### `watchlist`

決策 D10：估值紀錄全部用戶共用，觀察名單各自私人。

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| `id` | integer PK | 自動編號 |
| `user_id` | varchar(32) FK → `users.id`，索引 | 擁有者 |
| `ticker` | varchar(24)，索引 | 代號 |
| `company` | varchar(200) | 公司名稱 |
| `added_at` | timestamptz | 加入時間 |

唯一約束 `uq_watchlist_user_ticker`（`user_id`, `ticker`）：同一用戶不能重複加入同一代號。

| `id` | varchar(32) PK | UUID |
| `ticker` | varchar(24)，索引 | 代號 |

| `status` | varchar(16) | `done`、`failed`、`cancelled` |

| `ai_mode` | varchar(16) | `none`、`lite`、`standard`、`deep` |
| `source` | varchar(16) | `v2` 或 `legacy` |
| `error` | text | 失敗原因 |

| `price_date` | varchar(10) | 市價日期 |
| `trading_ccy` | varchar(8) | 交易貨幣 |

## 5. 市場數據

設計見 `docs/決策紀錄與路線圖-v2.1.md` 第 4 節。原則：

- **只存未調整的數字**：拆股不會改寫歷史價格；調整後價格與總回報由 `price_bars` 加 `corporate_actions` 即時計算。
- **只新增、不改寫**：排程更新時，來源改動過的數字先把舊值寫入 `price_revisions`，才更新。
- 系統用過的每個代號都會被追蹤並每日更新，歷史自然累積。查不到任何數據的代號會被刪除，不追蹤。

### `securities`

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| `ticker` | varchar(24) PK | 代號；匯率如 `USDHKD=X` |
| `name` | varchar(200) | 名稱 |
| `exchange` | varchar(40) | 交易所 |
| `currency` | varchar(8) | 報價貨幣 |
| `quote_type` | varchar(24) | `EQUITY`、`ETF`、`CURRENCY`、`INDEX` 等 |
| `timezone` | varchar(48) | 交易所時區 |
| `source` | varchar(24) | 數據來源，目前為 `yahoo` |
| `tracked` | boolean | 是否每日更新 |
| `first_date` | date | 最早一個交易日 |
| `last_date` | date | 最新一個交易日 |
| `bars` | integer | 交易日數 |
| `backfilled_at` | timestamptz | 完成回補全部歷史的時間 |
| `updated_at` | timestamptz | 最後更新時間 |
| `last_error` | text | 最後一次更新錯誤 |
| `checks` | json | 檢查結果，例如總回報與來源調整後價格的比對（`ok`、`warn`、`explained`、`skipped`） |
| `created_at` | timestamptz | 建立時間 |

### `price_bars`

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| `ticker` | varchar(24) PK，FK → `securities.ticker` | 刪除證券時一併刪除 |
| `date` | date PK | 交易日 |
| `open` | double | 開市價（未調整） |
| `high` | double | 最高價 |
| `low` | double | 最低價 |
| `close` | double | 收市價（未調整，當日實際成交） |
| `volume` | bigint | 成交量 |
| `source` | varchar(24) | 數據來源 |
| `fetched_at` | timestamptz | 取得時間 |

### `corporate_actions`

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| `ticker` | varchar(24) PK，FK → `securities.ticker` | 刪除證券時一併刪除 |
| `date` | date PK | 除息日或拆股生效日 |
| `kind` | varchar(12) PK | `dividend` 或 `split` |
| `value` | double | 派息：每股現金（未調整）；拆股：比例，例如 10 代表一拆十 |
| `source` | varchar(24) | 數據來源 |
| `fetched_at` | timestamptz | 取得時間 |

### `price_revisions`

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| `id` | integer PK | 自動編號 |
| `ticker` | varchar(24)，索引 | 代號（不設外鍵：證券刪除後仍保留修訂紀錄） |
| `date` | date | 被修正的交易日 |
| `field` | varchar(24) | `open`、`high`、`low`、`close`、`dividend`、`split`（成交量的修正不記錄） |
| `old` | double | 舊值 |
| `new` | double | 新值 |
| `source` | varchar(24) | 數據來源 |
| `seen_at` | timestamptz | 發現修正的時間 |

## 6. 資料庫以外的狀態

| 位置 | 內容 | 保存期限 |
| --- | --- | --- |
| Redis `sv:job:<id>`（未設 Redis 時在 API 程序記憶體） | 估值工作的進度與結果 | 2 天 |
| Redis `c:<key>`、`s:<key>`、`lk:<key>` | 公司資料等的共用快取、過期備用值、單一請求鎖 | 依用途 |
| Redis `rl:u:<scope>:<subject>` | 每位用戶的請求速率計數 | 一個時間窗 |
| `<APP_DATA_DIR>/runs/<job_id>/` | 每次估值的 Excel、calc JSON、報告（已蓋品牌） | 永久 |
| `<APP_DATA_DIR>/branding/` | Logo 與 PWA 圖示 | 永久 |

## 8. 計劃中的資料表（alpha.3 起）

以下依 `docs/財報數據與估值架構.md`，落實時再移入上方各節：

- 財報四層：原始（申報文件原文與取得紀錄）、申報（XBRL 事實）、標準（標準科目表的數值，附對照規則版本與來源）、檢查（每期的勾稽結果）。
- 調整方案（D12）：每個代號一個中央方案、每位用戶每個代號一個個人方案，全部版本保留。
- 組合分析（alpha.4）：保存的比較圖與最佳化場景。
