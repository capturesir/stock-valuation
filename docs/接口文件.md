# 接口文件（API）

- 適用版本：2.0.0-alpha.2 起
- 基本路徑：`/api/v1`
- 機讀合約：執行中的系統提供 OpenAPI 3.1（`/api/v1/openapi.json`）與互動文件（`/api/v1/docs`）。各欄位的完整型別以 OpenAPI 為準；本文件說明每個接口的用途、權限與要點。
- 以程式碼為準：路由在 `backend/app/routers/`，資料格式在 `backend/app/schemas.py`。本文件漏列任何接口，CI 的 `backend/tests/test_docs_sync.py` 會失敗。
- **維護規則**：每次新增、刪除或修改接口，都要同一個 PR 更新本文件。

## 1. 共同規則

### 1.1 登入與權限

| 方式 | 用於 | 做法 |
| --- | --- | --- |
| Cookie | 網頁 | `POST /auth/login` 設定 `sv_session`（HttpOnly、SameSite=Lax，30 天） |
| Bearer 令牌 | App、小程序 | `POST /auth/login` 帶 `issue_token: true`，之後每個請求加 `Authorization: Bearer <令牌>` |
| 查詢參數 | SSE 串流 | 瀏覽器的 EventSource 不能加標頭，可用 `?access_token=<令牌>` |
| 機器令牌 | 腳本、整合 | 環境變數 `APP_API_TOKEN` 的值作為 Bearer 令牌；不代表任何用戶，只能用不涉及個人資料的接口 |

權限分三級，下表「權限」欄使用：

- **公開**：不需登入。
- **登入**：任何已登入的用戶（`admin` 或 `member`）。
- **管理員**：只限 `admin`（決策 D6）。

連續登入失敗會鎖定帳號 15 分鐘。更改密碼後，該用戶其他裝置的登入狀態失效。

### 1.2 語言

錯誤訊息按 `Accept-Language` 回覆繁體中文、简体中文或 English（zh-TW／HK／MO → 繁體；zh-CN／SG → 简体；en → English；其他 → 繁體）。

### 1.3 錯誤格式

所有錯誤都附固定代碼，前端按代碼翻譯，不依賴文字：

```json
{ "detail": { "code": "invalid_ticker", "error": "代號「…」格式不正確" } }
```

| HTTP | 何時 | 常見代碼 |
| --- | --- | --- |
| 400 | 輸入有誤 | `invalid_ticker`、`wrong_password`、`brand_name_length`、`bad_request` |
| 401 | 未登入或登入已過期 | `login_required` |
| 403 | 權限不足 | `admin_required`、`user_required`（機器令牌用了個人接口） |
| 404 | 找不到 | 例如公司資料查無此代號 |
| 409 | 衝突 | `recent_valuation` |
| 422 | 欄位型別不符（FastAPI 驗證） | — |
| 429 | 超過請求速率 | `rate_limited`，附 `retry_after` 秒數與 `Retry-After` 標頭 |
| 503 | 估值佇列已滿 | `queue_full`，附 `retry_after` |

### 1.4 請求速率限制

管理員可在 `PUT /admin/limits` 調整，按用戶（未登入時按 IP）計算：

| 限制 | 套用到 |
| --- | --- |
| `lookup_per_minute` | `GET /stocks/{ticker}/lookup`、`GET /stocks/{ticker}/profile` |
| `prices_per_minute` | `GET /stocks/{ticker}/prices` |
| `valuations_per_hour` | `POST /valuations` |
| `concurrent_valuations_per_user`、`queue_max` | `POST /valuations` |
| `revalue_cooldown_hours` | `POST /valuations`（近期已估值時回 409） |

### 1.5 格式慣例

- 日期 `YYYY-MM-DD`；時間 ISO 8601（UTC）。
- 金額一律附貨幣欄位（`currency`、`trading_ccy`），不假設港元或美元。
- 代號不分大小寫，系統轉為大寫並檢查格式。

## 2. 接口一覽

### 2.1 系統

| 方法 | 路徑 | 權限 | 用途 | 回應 |
| --- | --- | --- | --- | --- |
| GET | `/api/v1/health` | 公開 | 服務、資料庫、佇列狀態與版本 | `Health` |

### 2.2 登入與個人帳號

| 方法 | 路徑 | 權限 | 用途 | 請求 → 回應 |
| --- | --- | --- | --- | --- |
| GET | `/api/v1/auth/status` | 公開 | 是否尚未建立任何帳號（登入頁提示用 CLI 建立第一個管理員） | → `AuthStatus` |
| POST | `/api/v1/auth/login` | 公開 | 登入；網頁設定 Cookie，`issue_token: true` 時回傳令牌 | `LoginIn` → `LoginOut` |
| POST | `/api/v1/auth/logout` | 公開 | 登出此裝置 | → 204 |
| GET | `/api/v1/auth/me` | 登入 | 目前登入的用戶 | → `UserOut` |
| PUT | `/api/v1/auth/me` | 登入 | 更改顯示名稱與偏好（顯示貨幣、再平衡、語言、主題） | `MeIn` → `UserOut` |
| PUT | `/api/v1/auth/me/password` | 登入 | 更改密碼；其他裝置會被登出 | `PasswordIn` → 204 |

### 2.3 用戶管理

| --- | --- | --- | --- | --- |
| GET | `/api/v1/admin/users` | 管理員 | 全部用戶 | → `UserOut[]` |

### 2.4 品牌設定（需求 5.2）

| 方法 | 路徑 | 權限 | 用途 | 請求 → 回應 |
| --- | --- | --- | --- | --- |
| GET | `/api/v1/branding` | 公開 | 系統名稱與 Logo 網址（登入頁也會用） | → `BrandingOut` |
| GET | `/api/v1/branding/logo/{variant}` | 公開 | Logo 檔案；`variant` 為 `light` 或 `dark`；SVG 以禁止腳本的 CSP 送出 | → PNG／SVG |
| GET | `/api/v1/branding/icon/{name}.png` | 公開 | 由淺色 PNG Logo 產生的 PWA 圖示；`name` 為 `192`、`512`、`512-maskable` | → PNG |
| GET | `/api/v1/branding/manifest.webmanifest` | 公開 | PWA manifest，名稱與圖示跟隨品牌設定 | → JSON |
| PUT | `/api/v1/admin/branding` | 管理員 | 更改系統名稱（1–40 字） | `BrandingIn` → `BrandingOut` |
| POST | `/api/v1/admin/branding/logo/{variant}` | 管理員 | 上傳 Logo（multipart 欄位 `file`；PNG 或 SVG，上限 512 KB、4096 像素） | → `BrandingOut` |
| DELETE | `/api/v1/admin/branding/logo/{variant}` | 管理員 | 移除 Logo | → `BrandingOut` |

### 2.5 股票與估值紀錄

| 方法 | 路徑 | 權限 | 用途 | 請求 → 回應 |
| --- | --- | --- | --- | --- |
| GET | `/api/v1/stocks/{ticker}/lookup` | 登入 | 查詢公司名稱與最新市價（不估值） | → 物件 |
| GET | `/api/v1/stocks/{ticker}/profile` | 登入 | 公司基本資料，查詢時先顯示，讓用戶核實代號；來源暫時不可用時回傳過期備用值並標示 `stale` | → `StockProfile`；404 查無此代號 |
| GET | `/api/v1/stocks/{ticker}/valuations` | 登入 | 走勢圖資料：每次估值的各方法、各情境結果與當時市價（全部用戶共用，決策 D10） | → `StockValuations` |
| GET | `/api/v1/stocks/{ticker}/prices?days=` | 登入 | 每日價格，含未調整收市價與系統計算的調整後價格；首次使用某代號時自動回補全部歷史 | → `PriceSeries` |
| GET | `/api/v1/runs/{run_id}/excel` | 登入 | 下載該次估值的 Excel（已蓋品牌） | → xlsx |

### 2.6 觀察名單（每位用戶私人）

| 方法 | 路徑 | 權限 | 用途 | 請求 → 回應 |
| --- | --- | --- | --- | --- |
| GET | `/api/v1/watchlist` | 登入 | 自己的觀察名單，附每檔最新估值 | → `WatchlistEntry[]` |
| POST | `/api/v1/watchlist` | 登入 | 加入 | `WatchlistIn` → 201 `WatchlistEntry` |

### 2.7 估值工作

| 方法 | 路徑 | 權限 | 用途 | 請求 → 回應 |
| --- | --- | --- | --- | --- |
| GET | `/api/v1/ai/plan?ticker=&mode=&tasks=` | 登入 | AI 工作清單：每項預估 Token 與費用、是否可用、略過原因（`skip_code`） | → `Plan` |
| POST | `/api/v1/valuations` | 登入 | 開始估值（背景執行） | `ValuateIn` → 見下 |
| GET | `/api/v1/jobs` | 登入 | 進行中的工作 | → `Job[]` |
| GET | `/api/v1/jobs/{job_id}` | 登入 | 工作狀態（輪詢用，小程序適用） | → `Job` |
| POST | `/api/v1/jobs/{job_id}/cancel` | 登入 | 停止估值；已完成的步驟保留 | → `Job` |
| GET | `/api/v1/jobs/{job_id}/events` | 登入 | 工作進度串流（Server-Sent Events，斷線 2 秒後重連） | → `text/event-stream` |

`POST /valuations` 的回應：

| HTTP | 意思 |
| --- | --- |
| 202 | 已建立新工作 |
| 200 | 同一代號已在估值，加入該工作（`joined: true`） |
| 409 | 近期已用相同條件估值（`recent_valuation`）；帶 `force: true` 重算 |
| 429 | 超過每小時估值次數或同時估值數 |
| 503 | 佇列已滿（`queue_full`） |

估值一次只執行一個（v1 引擎寫入共用資料夾），其餘排隊，`Job.queue_position` 顯示位置。

## 3. 計劃中的接口（alpha.3 起）

落實時移入第 2 節：

- 財報（alpha.3）：標準化財報、每個數字的來源追溯、檢查結果；調整方案（D12）的中央方案與個人方案、版本紀錄。
- 組合分析（alpha.4）：走勢比較、指標計算、投資組合最佳化、保存的場景。
- 估值方法（beta.1）：各方法結果與綜合理論價。
- AI 任務（beta.2）：建議的採用／忽略與來源。
